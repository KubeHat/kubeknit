# v0.1.0 (unreleased)

First release of kubeknit, forked from [konfig](https://github.com/corneliusweig/konfig) v0.2.6.
Issue numbers refer to the konfig repository.

## New features
- `kubeknit delete [--save] [--context-only] <CONTEXT>..` deletes contexts from your kubeconfig, together with
  clusters and users that are no longer used (#4, #15).
- `kubeknit import --force` overwrites existing clusters, users and contexts (#43).
- `kubeknit import` warns when an imported cluster, user or context has the same name as an existing one,
  but different settings, instead of silently dropping it (#31, #43).
- `kubeknit completion bash|zsh` prints a shell completion script, which also completes context names (#6).
- `kubeknit version` prints the version.
- `kubeknit import -` reads from stdin, like `--stdin`.
- `export --kubeconfig=<CONFIG>` is accepted.
- The kubectl binary can be set with the `KUBEKNIT_KUBECTL` environment variable.

## Bug fixes
- `import --save` wrote to `$XDG_CACHE_HOME/config` when `XDG_CACHE_HOME` was set, so the kubeconfig never
  changed. It now writes to the first file in `KUBECONFIG`, or `~/.kube/config` (#46, #47, #48, #49).
- `import` merged all files from `KUBECONFIG` into the saved kubeconfig. Now only the target kubeconfig is used.
- Temporary files were created in the current directory, which failed in read-only directories and could leave
  `konfig_*` files behind (#45). They now live in a private directory under `$TMPDIR`.
- kubectl output is piped instead of redirected, which avoids
  `error: write /dev/stdout: permission denied` with sandboxed kubectl builds such as snap (#14, #37, #41, #42).
- Restoring the kubeconfig after a failed `import --save` was broken. The kubeconfig is now only written
  after the merge succeeded, and in-place, so symlinks and file permissions are kept (#26).
- Flags given after the configs, e.g. `kubeknit import cfg --save`, consumed the wrong arguments.
- `import --stdin` was ignored unless stdin was a pipe, e.g. `kubeknit import -i < cfg` did nothing.
- `import --preserve-structure` broke relative certificate paths. They are now made absolute.
- `merge`, `import` and `export` silently ignored missing kubeconfig files.
- `merge` without arguments printed the default kubeconfig instead of an error.
- `export -k` without a value failed with an unhelpful error.
- `IFS` was changed globally while merging (#44).

## Other
- Tests no longer depend on the kubectl version and never touch your real `~/.kube/config`.
- CI uses current GitHub actions and downloads kubectl from `dl.k8s.io`.
